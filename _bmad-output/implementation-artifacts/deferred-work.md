## Deferred from: code review of 1-2-the-event-bus-admission-control-and-the-lease-primitive (2026-07-26)

_Citations name a **file and a symbol**, per the policy adopted in the 1-1 section above. Any number is a pointer, not a fact._

- **`writeLease`'s atomic write uses a fixed temp filename, so concurrent writers to one owner directory can swap ownership or crash** — `packages/core/src/runner/lease.ts`, `writeLease`. The temp path is derived from the owner directory alone (`const tmp = file + ".tmp"`, ≈`:60`) with no pid, token or random suffix, then `io.writeFileSync(tmp, …)` is followed by `io.renameSync(tmp, file)`. Two writers to the same directory interleave badly: writer B overwrites the shared tmp before writer A renames, so **A's `renameSync` promotes B's record under A's own call** — the surviving `.runner-lease` names the wrong `pid`/`token` — and B's subsequent `renameSync` then throws `ENOENT` because the tmp file A already consumed is gone. That is exactly the scenario a lease exists to arbitrate: an old owner's `heartbeatLease` racing a new owner's post-reclaim `writeLease` on the same root. The module header's MOAT paragraph reasons only about a **stale** lease ("at worst a false-positive `failed`, never an auto-`done`") and does not cover a **torn** one that is fresh but attributed to the wrong owner — a liveness oracle answering confidently and wrongly, which `runner/liveness.ts` and `runner/recover.ts` both consume.
  - **Pre-existing, and deliberately not fixed in story 1.2.** Re-measured on the working tree at `34379cf`: `git diff 578e5b4..34379cf -- packages/core/src/runner/lease.ts` touches the write path on exactly one line, `io.mkdirSync(loomDir, …)` → `io.mkdirSync(ownerDir, …)`, which is T-C1's owner-neutral parameter rename. The tmp derivation, the `writeFileSync` and the `renameSync` are byte-identical to baseline. Story 1.2 was scoped to generalize this primitive, not to re-engineer it.
  - **Why it is worth recording now rather than leaving silent.** Story 1.2 is the commit that promotes `writeLease` from a per-loom helper to THE two-lifetime primitive (AD-16) and adds `packages/core/src/sessions.ts` as a second caller surface (`writeSessionLease`, `heartbeatSessionLease`). The race is unchanged per directory, but the number of directories and call sites exercising it just grew, and the session lifetime is the one whose co-tenant (`apps/web/lib/session-log.ts`) already writes into the same directory from a different process.
  - **Fix when it bites:** give the temp path per-writer uniqueness — `${file}.${process.pid}.${token}.tmp` is enough, and both fields are already in hand at the call — since `renameSync` within a directory is atomic once each writer owns its own source path. Note the injectable `LeaseFs` seam makes this directly testable without real I/O, which is how the failure above was reproduced during review. Cheap, local, and it does not change the record shape, the filename, or any exported signature.
