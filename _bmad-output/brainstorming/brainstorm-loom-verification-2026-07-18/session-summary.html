The verification flow — two altitudes, one moat

Prepare — readiness node

Proves the recipe: install → generate → migrate → seed → probe. Fail-closed: no lab, no experiment. Blocks before build spend, parks with a clear question.

Threads — "does the code hold?"

bmad-style review + checks + tests. Serviceless, parallel, cheap. Streams live rungs = mid-run evidence = progress heartbeat.

Loom verify — "is this what you asked?"

The playground: lane up in the loom worktree, borrowed infra, seeded data, live Playwright, capability-walled agents. Finds bugs → sends itself back. Feel-critic rides the same slot. Mutexed per repo.

Ready — you judge the product

Delivery card: claim + proof + narrative + risks. One click opens the live window — judge it in work.

↩ Not approved? Boomerang: send it back with feedback — same branch, same worktree, same recipe. Steering, not death.

Accept → mechanical landing

Rebase onto moved main → re-verify same contract (under the mutex) → merge. Clean pass lands silently; integration repair adds a delta note; failure re-opens and knocks only if repair exhausts.

Done — teardown

Leases released, tenant DBs dropped, worktree folded. Like it was never here.

🚨 The dire razor

Dire = the loom has no path to advance without you. Parked on credits, blocked on a credential, crash-looped, repair not converging → push (awareness-only, phone). Everything else → window.

Two liveness layers: the supervisor watches processes (restart-on-death, crash-loop breaker); the orchestrator watches progress — the evidence-rung heartbeat. Flatline = dire even when every light is green. Hard stall pushes in seconds; soft flatline gets ~10 min of self-rescue.

🪟 Windows, not doorbells

Cheap projects: always-warm window. Heavy projects: window-on-demand — opening it is the pull; telar stands the lane while you look. "Preview this thread" = ephemeral lane on a thread worktree.

📱 Flagged for later

Companion website (Vercel-hosted) to answer escalations remotely. Relay-only, local telar stays sole executor; remote accept needs its own design pass.

Decisions on the record

  • Agents declare, telar spawns — ownership by construction; idempotent ensure kills duplicate servers; processes visible in UI for sessions & looms
  • Two-altitude verification — threads prove code (streaming), the mutexed playground proves the ask
  • Borrow, don't hold — labs exist per verify event; per-repo verification mutex; fleet heavy-infra budget
  • Worktree doctrine — user checkout sacred · per-loom mandatory · per-thread optional
  • Branch-per-loom, landing queue — concurrent proof of branches, serial proof of combinations
  • Accept-then-land — judge the finished product in work; landing is mechanical behind you
  • Rejection = boomerang — send back with feedback; same branch, worktree, recipe
  • Silent stall is the enemy — progress heartbeat; dire razor; awareness-only pushes
  • Trust wall — sessions may adopt foreign stacks; looms never; evidence only from telar-owned labs
  • Sessions & looms share one primitive — same supervisor, different owners; readiness node = first client
