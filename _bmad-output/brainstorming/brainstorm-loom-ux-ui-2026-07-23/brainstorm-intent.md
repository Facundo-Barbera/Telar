# Loom UX/UI — Intent

> Source: brainstorming session 2026-07-23 (`.memlog.md` in this folder is the canonical log).
> Purpose: lean input for `bmad-spec` / `bmad-prd`. Turns the loom-system + loom-verification outcomes (2026-07-18) into six concrete UX surfaces, prototyped live as demo-gallery entries under `apps/web/lib/demo-gallery/**`. **These are design-source-of-truth prototypes, not production code** — production still runs the current dashboard and `session-view.tsx`.

## The six final surfaces

**UX 0 · Birth of a loom** (`birth/`, entry `birth-dial`) — the front door. One real session (production bubble idiom, `WorkingIndicator`, composer) is where every ask starts. Below the simple-task boundary the agent just does it inline ("Do it here" — no loom, no graph, a screenshot closes it). Above it, "Spin off" leaves exactly two things in the chat: a detach marker and a one-line mono receipt ("premise + context · detached") — no graph preview, no progress narration, no loom door inside the session. One design plays at every weight (one stitch / few stitches / tapestry); size shows only in how much the loom's own graph does, never in a different UI.

**UX 1 · Home** (`home/`, entry `home-current`) — a graft onto the existing production dashboard, not a replacement. Same KPI hero, two-column command deck, rails and panel grammar. "Needs you" moves to top-left and splits into a compressed delivery-shelf row (claim, proof tally, risk flag, Accept/Boomerang) and the parked question verbatim (answering resumes the loom). "Running now" rows gain an act chip (prepare/build/verify/repair/parked) and evidence age. Right column keeps Recent sessions (looms are born there) and adds a Done-today receipt and Hot projects carrying a map drift note. Three from-scratch proposals (two-band triage / delivery inbox / map-as-home) were explored and superseded; their ideas live on inside the graft.

**UX 2 · Loom detail** (`loom-detail/`, entries `loom-detail-walkable` + `loom-detail-walkable-scale`) — the walkable cockpit, one design in two load variants sharing a component kit (`cockpit.tsx`: `ActTab`, `Room`, `ConductorCard`, `ThreadGroup`, `ContractGroups`, `LabRoom`). Persistent Prepare/Execute/Judge act tabs, park/kill verbs in the header. Prepare renders the same sealed DAG map as the gate room (UX 4). Execute pins the conductor (holds-no-pen, beat-vs-flatline heartbeat) over dense thread rows; drilling a thread opens the team view — compiled flow, per-node context manifests, builder lanes in worktrees, thread-altitude rungs, and per-agent transcripts in a right drawer with live streaming. Judge shows the contract lighting up as work completes. Header carries the WINDOW (live merged-so-far URL, on-demand borrow at scale), the LAB (service registry — scope, lease token, trust wall), and CHATS (steering thread always open, intake reopenable). The scale variant (novarix, 11 threads / 3 workstream labels / one orchestrator) demonstrates the full live-escalation path: amber attention strip, pinned chats row, "N needs you" tab meta, ladder inner→mediation→you.

**UX 3 · Delivery card** (`delivery/`, entry `delivery-final`) — the accept surface, converged from three proposals (the dossier / the coffee inbox / see-it-in-work) that turned out to be altitudes of one judgment, not rivals. The SHELF is the fleet-scale skim: claim, proof strip, risk flags, release grade, verdict in place. Opening a card is taste-first: the live product on its frozen final-verify lane leads, a filmstrip flips between the live lane and ledger screenshots; below the glass the courtroom scrolls — reality manifest, cited narrative (the one uncited claim wears "unverified"), contract with per-assert citations, provenance-stamped evidence ledger, full attempt history with flaky flags, vision critic's advisory verdict. A shared `VerdictBar` (Accept declares the map note and queues silent landing; Boomerang opens the composer, send = resume) is one verdict per delivery, shared between shelf row and open card.

**UX 4 · Readiness gate** (`prep-gate/`, entry `prep-gate-final`) — "the gate room," merged from proposal A (war table, direct manipulation) and B (two-handed: chat left, graph right), leaning B. The preparation DAG is a pan/zoom map center-stage (grab-drag pan, cursor-anchored wheel zoom, rounded 90° elbow SVG edges, node text that never truncates). Clicking a node inverts the proportions: a dominant left pane opens that node's conversation (history rail, "+ new chat," composer), the map shrinks right and zooms only itself. The gate is a node like any other — its session is the steering chat (chips fire real edits) and its pane carries the verdict controls (unprovables first, degraded-mode ack gates Accept, Modify wakes nodes, Deny → straight to dev). Waking a dormant node (e.g. the PRD) triggers an approval-gated `advance_node` call; approving grows a new elbow edge into flow compile, an audited recompile.

**UX 5 · Workspace** (`workspace/`, entries `workspace-home`, `workspace-queue`, `workspace-packet`, `workspace-in-session`) — the project-less front door, originally designed in the 2026-07-23 organization-workspace brainstorm and integrated here. Master chat is a real session (production bubble idiom); agent-created items land on a right-rail Desk, dismissing drains to the queue (never deletes). Both loom handoffs from this surface now speak birth doctrine: the queue's "Weave as one loom" batch action yields the UX 0 detach receipt in place; a ripened work packet's "Plan loom from this packet" hands over premise (fixed brief + acceptance) + context (attachments) and the packet stays behind as an origin receipt. A fourth entry shows tasks as a Telar-wide substrate reachable from any session via workspace MCP.

## Doctrine locked this session

- **Looms are born from sessions, and detach.** Every loom starts as a session (a project session, or a session inside the loom itself); the session's entire role in a birth is handing over the **premise + maybe some context** — nothing more. The loom then detaches; it never sticks to that chat.
- **The decision graph always exists.** It is not decoration or an optional ceremony step — every element of the graph is an actual session that must happen or be explicitly skipped before the loom can start.
- **The graph is a true branching DAG that converges.** Not a linear checklist: nodes bloom (one divides into several), branches close back together, and the whole thing eventually converges into the gate. Drift-spawned nodes and waking a dormant node both grow new edges live.
- **ONE design for looms, at any size.** There is no small/medium/large UI split. The simple-task boundary means small work stays a plain **session** (no loom, no graph at all) — the moment something becomes a loom it takes the full shape: detach + graph-of-sessions + gate + cockpit + delivery. Size shows only in how many node-sessions run vs. skip and how long they take.
- **Agents advance graph nodes only via approval-gated tool calls.** `advance_node`, `weave_batch`, and the ack-gated Accept are all the same protocol shape: proposal → explicit human approval → the effect happens. This is now doctrine everywhere a model wants to move a node forward.
- **The graph is never shown inside the session's UI.** The birth session shows only the detach marker and receipt; the graph-of-sessions belongs entirely to the loom's own pages, never to the originating chat (this was corrected twice before landing).
- **Ceremony scales, the walls never do.** The dial (tiny/few/tapestry) changes how much process is visible, never whether the three structural walls hold: **branch** (isolated work), **evidence** (proof accumulates), **human-accept** (the accept moat) survive at every weight — even the one-stitch loom still gets a worktree and a screenshot, and "Land it" IS the accept moat.

## Shared design language

- **Map/DAG rendering rules** (the gate room's kit, later generalized and reused as the frozen Prepare receipt in the UX 2 cockpit via `GateGraph(nodes, edges, gateState)`): grab-to-pan viewport (not a scroll container), scroll-wheel zoom anchored at the cursor, rounded 90°-elbow SVG edges, node sub-text that never truncates (short one-line sub always visible; the **selected** node expands — downward only, into the row gap, never overlapping a neighbor — to reveal full detail; every other node dims to 65%). Glide-to-node measures after a double `requestAnimationFrame` with an eased cubic-bezier to kill flicker. A "sealed" gate state (muted lock) renders the same map as a frozen receipt.
- **Detach receipt grammar**: one mono line — *"premise + context · detached"* — is the universal handoff idiom, identical whether it fires from the birth session (UX 0), the workspace queue's batch weave (UX 5), or a ripening packet's loom handoff (UX 5).
- **ApprovalCard idiom**: mono header ("tool call — awaiting your approval"), the proposal text, Approve/Hold. One component, one protocol shape, used for every approval-gated advance (`advance_node`, `weave_batch`, the degraded-mode ack).
- **Tone law**: no suggestion-text or doctrine captions anywhere in the UI (e.g. never render "threads land serially, on green") — surfaces show only state and data, purged across every finished lane.
- **One shared fictional day, across lanes, for judgeable coherence**: cross-lane continuity is what let the session judge whether "Telar feels like a whole." Aurora payments-retry is the hero delivery on the home dashboard and recurs across surfaces; novarix search-filters is born (UX 0), drafts at home (UX 1), and is gated (UX 4) across three surfaces; ozom client-role-seeding anchors the UX 2 baseline; novarix P12 usage-based billing anchors the UX 2 scale variant and its live escalation.

## Conversation component extraction

The session's closing move: the chat window was hand-rebuilt in all six lanes with the same anatomy (transcript + optional composer + optional right rail + inline tool activity) — proof it should be one component, named `Conversation` (domain word "session" stays as one kind of *owner*, not the UI). Three layers: **primitives** (`Message`, `ToolStep`, `WorkingIndicator`, plus two new ones the demos proved out — `Marker` for dashed system events and `ApprovalCard`); the **`Conversation` shell** (item-kind registry for the transcript, pluggable composer/right-rail/header slots, owns scrolling/streaming, owns no data-fetching or session semantics); and **owner adapters** per surface (project session, master chat, loom node chat, intake/steering/escalation, read-only transcript). Migration is a pure-render carve-out of `session-view.tsx` at the render seam, proven in the demo gallery before new surfaces (master chat, node chats) are born on it. Full plan: `conversation-component.md` in this folder.

## Open items / flagged futures

- **Workstream-grouping provenance** — grouping Execute's thread rows by workstream label (novarix scale variant) is a **new idea from this session**, not sourced from the July-18 docs (which only say interference analysis shapes decomposition width). Flagged unvalidated; open proposal for the spec. Alternatives to weigh: flat thread list, or filter chips instead of persistent grouping.
- **Preview-this-thread escape hatch** — identified as a cockpit gap during the mid-session fit audit and never designed. Still missing from the final UX 2 cockpit.
- **Fleet landing queue + stacked looms + a map-level fleet surface** — deferred-by-design during the fit audit; UX 1's final graft covers the dashboard but does not visualize serial landing-queue state or a project/region map at the fleet level.
- **Batch framing is thin in the fixtures** — the loom-system doctrine that a loom may carry multiple tasks (sized by its accept moment, not intent count) is only demonstrated end-to-end in UX 5's queue-weave handoff; UX 0/UX 2/UX 4 fixtures all use a single goal sentence, so "loom ≠ one task" isn't visibly proven at the cockpit/gate altitude.

## How to walk it

Run the app and open **`/demo-gallery`**. The sidebar groups walk the surfaces in order — **UX 0 · Birth of a loom** through **UX 5 · Workspace** — each a self-contained, live (`use client`) React prototype over shared fixtures for the one fictional day described above.
