PRELUDE the method

Design by shipping fakes

No slide deck, no whiteboard photos. Every proposal became a real gallery entry — a live page, wired with fixtures, sometimes interactive — added to the running product's own demo gallery. Convergence happened by looking at competing entries side by side and picking, not by arguing about descriptions of them. A single fictional day held everything together so that judging one surface meant judging how it felt next to the others.

ACT II the long convergence

Finding the loom underneath the tabs

Three rooms won the first look, but a return to the full source docs found the view too shallow — no thread detail, no orchestrator, no sense that a loom is a team. What followed was the session's longest arc: two more proposals, a demand for realism, a user-caught invented layer, and finally one shared component kit doing the work of both variants.

  • Gap found: loom detail needed a thread drill-in (compiled flow DAG, context manifests, bounded recompiles) and an orchestrator seat (role wall, decision log, mediation ladder, a heartbeat that flatlines on trouble).
  • Realism demanded: gallery entries could now be interactive — state, animation, real components — "landing the feeling that this is a loom" mattered more than static wireframes.

course-correction — caught by the coach's own audit

The Prepare room was showing the wrong graph

A stress-test at scale surfaced it: Prepare had been rendering the execution plan — flow compile's output — when it should have been rendering the preparation graph itself: living model → opening conversation → nodes spawned only where drift exists (dormant, dashed, "no drift, no node") → readiness → flow compile. The execution plan got demoted to a receipt line on the flow-compile node. Two compiles were named and kept apart for good: the loom's own flow compile, and each thread's separate one during execute — never to be fused in the UI.

course-correction — caught by the user

Sub-orchestration was an invented layer

The at-scale loom had grown a fictional rung: intermediate sub-orchestrators between threads and the conductor. The user didn't buy it — sub-orchestration is per thread, the thread's own main agent already plays that part. The fix demoted the invented agents to workstream labels, put one orchestrator over all eleven threads, and cut the ladder back to its true three rungs. A related idea — grouping threads by workstream at all — got flagged honestly as unvalidated, a new idea from this session rather than the source docs, and left as an open proposal.

A fit audit against both full source memlogs (185 entries between them) turned up real gaps: the window (a live URL of merged-so-far state, borrowable on demand), the lab (a services registry with scope, trust wall, lease token), loom-level pause / kill, and a preview escape hatch. All four got built into the cockpit before it was allowed to call itself finished.

final polish

One design, not two

The two variants — baseline and at-scale — still disagreed on card shapes and sizes. cockpit.tsx became the shared kit (ActTab, Room, ConductorCard, ThreadGroup, ContractGroups, LabRoom) so both walkables draw from the same components. They now differ only in data, grouping, and the escalation path — never in layout.

interlude — the reckoning
"the graph looks too solid — chat interfaces, the welcoming part of an AI app, are being stripped away. automation is the goal, but control must go to the user when and where it matters."

Four surfaces in, the worry surfaced: the UI's rigidity was hard-constraining every loom toward huge tasks and inviting none of the small ones. The diagnosis landed hard — the middle and the end of the loom (cockpit, delivery, gate) had been designed at maximum ceremony, and its birth had never been designed at all. The flexibility material had been sitting in the source docs the whole time, underweighted: an adaptive-ceremony dial, a simple-task boundary, sessions as the chat-first primitive.

ACT IV the gate room

From two hands to one graph

The pre-gate surface — the real Accept / Modify / Deny moment — opened with a direct fork: manipulate the graph, or talk to a conversation that moves it for you.

A · The war table
Graph-first, direct manipulation. Click a node to inspect; modify wakes a dormant PRD and the flow recompiles, audited. Gate rides a fixed bottom bar.
B · The two-handed gate
Conversation on the left — chips fire real edits — a live graph on the right reacts with a recompile spinner. The verdict is the conversation's last word.

The verdict on the first DAG draft: liked — now make the edges 90° rounded elbows, make the graph the default view where clicking a node zooms the conversation into the main attraction, and give every node multiple chats — history, a way to add more, an approval-gated tool to advance the work. Mid-build, one more requirement landed: the graph should be a grabbable map, click-and-drag to pan — never a scrolling container.

drag to panscroll to zoomclick a node

The preparation graph, reconstructed — try it: drag the empty space to pan, click any node to open it (the rest dim to 65%, per the actual doctrine), and wake the dormant PRD to watch the graph grow a new edge live.

convergence — A + B, leaning B

The gate room

The graph lives center-stage, the stage itself. Click a node and a left pane opens with its conversation — the zoom applies only to the map, focusing the node you're in. Scroll wheel zooms the graph, never the page. Node text is never allowed to truncate. And when a session is open, the proportions invert: the conversation pane dominates, the map shrinks to a side thumbnail. The gate itself is just another node — its "session" is the steering chat plus the verdict controls.

Three more passes chased the feel: a flicker traced to measuring the viewport before layout settled (fixed with a double animation-frame measure and an eased transform); an expand-on-click that first overlapped its neighbor, fixed by growing only downward into the row gap while every other node dims; and a spacing pass that widened the whole canvas so an expanded node never crowds its row.

The dial scales ceremony, never the walls: branch, evidence, and human accept survive at every size. A first build proved the idea — one chat, one composer, three weight tabs, the heaviest of which unfolded the readiness gate's own graph inline. It felt dull. The fix: rebuild directly on the production chat components — real message bubbles, the real working indicator with its ticking clock and tool states, a real composer — so birth felt like using Telar, not a mockup of it.

doctrine correction

Looms detach from the chat

Every loom is born from a session — a project chat, or a chat inside the loom itself — but it detaches from that chat. It never sticks to it. The decision graph is not decoration: it must always exist for every loom, and each element of the graph is an actual session that has to happen, or be explicitly skipped, before the loom can start. And there is one single design for looms — never a small / medium / large split. Size shows only in how many node-sessions run versus skip, and how long they take. Never in a different UI.

The corollary drew the actual line: the simple-task boundary means small work simply stays a session — no loom, no graph, sessions are for exactly that. The instant it becomes a loom, it takes the full shape at once: detach, graph-of-sessions, gate, cockpit, delivery.

doctrine correction, no. 2

The graph is never the session's business

Showing the loom's graph inside the birth session's own UI confuses future agents about what owns what. The birth session creates the premise — and maybe a little context — and that is all. Every subsequent section of the graph gets its own separate conversation. And the graph itself had been drawn too politely linear: nodes actually branch — one divides into two, those into others — and everything converges at the end into something that closes. A growing thing, not a checklist.

synthesis

Every correction was the same correction. Don't let structure eat the conversation.

The rigidity worry became an architecture. The complaint that the graph looked too solid became the birth doctrine (detach, hand off premise and context); the doctrine's corollary made nodes into conversations; that made the chat shell worth extracting as its own component. The session's closing idea is its opening worry, resolved one layer down.
The gate room is where the two source sessions actually meet. The system session's preparation graph, rendered as a map whose every node is the verification session's "session with an owner." The detach receipt — premise plus context — became the one handoff grammar used everywhere: birth, the queue's weave, the workspace packet. "Taste it first" and "windows, not doorbells" turned out to be one value: experience before explanation, pull before push.
The method was a finding too. Shipping fakes into a live gallery, judged over one shared fictional day, is what let cross-lane continuity — payments-retry recurring across four surfaces, search-filters born and prepped and run across three — prove that Telar feels like one thing, not six demos.
