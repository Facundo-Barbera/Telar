# Ultra — Session UI Contract (frozen)

Binds CAP-2 (real session UI). As-built reference rendering: `apps/web/lib/demo-gallery/ultra/session-ultra.tsx` (fixtures-only mockup — already shipped). House rules apply: terse copy, `min-w-0` + `truncate` on variable-width flex children, density over height, no placebo, masked shimmer only. State names are the as-built `running | done | failed | stopped`.

1. **Context — a session, not a stage.** Everything renders inside real session-window chrome: header, transcript, composer, and the existing sub-agent rail. No standalone Ultra surface. The composer Ultra chip is a normal composer control.
2. **Anchor — a side quest, not a window.** Each run is ONE compact fixed-height tool-style row in the transcript: run name, state pill, agents done/total, quiet spend readout (`$` Claude / tokens Codex), thin progress sliver. Fixed-height while running — never grows or reflows; conversation continues beneath it. Its sole permitted height change is a one-time collapse to a one-liner on reaching a terminal state — no per-tick resize. Clicking it focuses that run in the rail.
3. **Rail — Workflows section.** The existing sub-agent rail gains a Workflows section listing every run of the session. A run card shows name + state + spend and carries Stop; phase groups hold per-agent rows (`label` · state · `model·effort` chip · masked-shimmer live snippet · tokens/cost); a fixed-height scrolling narrator `log()` window (no layout shift, ever). Clicking an agent row opens its transcript as a sub-agent tab does today. A Script tab shows the script read-only (model pins visible) plus a link-out to the authoring reference (CAP-3).
4. **Multiple runs.** Anchors stack in the transcript where launched; all runs list together in the rail. Concurrent live runs are a supported, first-class case.
5. **Main-agent control.** The UI must accommodate: the agent launching a run (tool call → immediate `runId`), conversation continuing while it runs, the agent stopping a run by tool call (visible in anchor + rail), the agent reacting to a completion event by summarizing in chat, and a validation rejection (e.g. a `model`-less script) returning to the agent, which re-authors.
6. **No budget UI anywhere.** No meters, ceilings, or reserved headroom — spend readouts only. The composer Ultra chip just arms (no ceiling editor, no submenu).
7. **Terminal states.** `done` / `stopped` / `failed` chips. `stopped` and `failed` show a Resume affordance; `failed` shows the terse terminal error. `done` triggers the anchor's one permitted collapse; the result stays reachable from the rail card.
8. **Replay** (Play / Pause / Restart / speed on virtual time) is mockup-only — shipped in the demo gallery, not part of the real UI.
9. **Dock.** A session with live runs shows run state in its dock bubble (name · state · spend); tapping re-focuses the run. One dock signal per session; live runs summarize. Bound by CAP-6 — polish tier; implementation shape is open.

Data sources: `GET /api/ultra/[id]/events` SSE (`run` snapshot / `ev` deltas / `end`), `GET /api/ultra/[id]/agents/[ordinal]` for agent transcripts, `POST /api/ultra/[id]/stop|resume` for controls. Native `EventSource`, per project-context.md.
