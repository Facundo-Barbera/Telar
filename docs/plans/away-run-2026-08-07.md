## Decision log

- **The refusal ladder's rung (a) heals on the next send, not in-flight**
  (STEP 4 commit). The design sketched an invisible same-POST re-run; wrapping
  the route's whole acquire-and-consume block in a retry loop was judged too
  risky a restructure. Instead a refusal re-arms the fork unguarded and closes
  the runtime, so the user's next send lands the documented unguarded
  truncation — visible as one failed send in a rare race, never silently
  wrong. Veto by asking for the in-flight retry.
- **"Remove this exchange" applies by re-seeding from the persisted record**
  rather than surgically editing local state — one source of truth, and the
  identical path a second tab takes through the feed's rolled_back line.

(Product-feel calls made without the owner. Newest first. Veto anything here
and the code moves — each entry names its commit.)

- **The walk previews; commit is typing or sending** (STEP 1 commit). The
  design left open when a walked-to line actually leaves the strip. Chosen:
  browsing (ArrowUp/ArrowDown/Escape) never removes anything — the line
  leaves only when the user types into it or sends it. Rationale: "nothing
  is destroyed before you send" is the family's own grammar sentence, and a
  browse that consumed lines would need re-queue churn to undo.
- **"Needs your approval" outranks "Working…" everywhere it renders** (task
  #20 commit). An unanswered card means work is paused ON the user, so the
  sidebar row's dot, meta line, and hover card all show it first — steady
  amber (the Marker attention pair), in words, no icon-only state. Rationale:
  feel-contract "background presence in words"; the one sidebar state whose
  job is to interrupt.
