How a Telar conversation works

The path a message takes, what we fixed today, and the simpler shape it should have. · Aug 8, 2026

Today — messages come in from many doors

Everything that can start the agent working funnels into one rule: one turn at a time. But there are four different waiting rooms on the way, and half the doors only work while you have the conversation open on screen.

What went wrong (and where it stands)

Every bug you've hit lately is one of these — and they're all the same story: a door, a waiting room, or a delivery that didn't follow the rules.

FIXED The repeating divider

Reconnecting to a busy chat replayed the whole story from the top, and the "Compacted" divider got drawn again each time.

FIXED The looping "ultra stopped"

A stopped Ultra's "you should know this finished" note could never be marked as delivered, so the chat kept announcing it forever — but only while you were watching.

FIXED Work vanishing on reload

If the agent's process died while background work was reporting in, everything you'd watched arrive was never saved.

FIXED Codex told twice (forever)

Codex chats were re-told every finished Ultra on every message, while the UI said "not delivered yet".

OPEN Stuck messages

A queued message with no tab open has nothing to wake it up. There's no timer — it waits until something else pokes the session.

OPEN Two ways to send

The main chat and the dock deliver your message differently. Usually invisible — until they race.

OPEN Blind background events

Ultra finishes and loom questions only reach the agent while a tab is showing that chat. Close the tab, and nothing moves.

The shape it should have

One waiting line. One dispatcher. Everything — your messages and background events — becomes a ticket in the same line, each ticket unique so nothing can ever loop or double-fire. Tabs just watch; nothing depends on them being open.

What I'd like your call on

1 · Should background events stop depending on open tabs?

Move them server-side into the waiting line. This kills the whole "only breaks while you're watching" family for good. My recommendation: yes.

2 · Add the timer?

A gentle pulse (only while something is waiting) so a queued message can never get stuck. Cheap, boring, effective. My recommendation: yes.

3 · Make the dock and the chat send the same way?

One delivery path for every surface. Costs maybe a millisecond on the fast path, removes a whole class of races.

4 · "Send now" into a running turn?

Today a message typed mid-turn waits its turn. Claude Code can nudge a working agent mid-stream — Telar's plumbing could too. Nice-to-have, after the basics.

5 · Show the machinery?

When the system wakes the agent for a finished Ultra, the chat currently shows nothing until words arrive. A small honest line — "waking for ultra sweep…" — would end the "is it doing anything?" doubt.
